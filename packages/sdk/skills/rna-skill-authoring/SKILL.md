---
name: Professional skill authoring
description: Turn domain knowledge and observed practice into specific, reusable skills with examples, validation and recovery.
---

Use when creating or improving a project skill. A skill teaches a reliable procedure; it is not a role description or a list of virtues.

First identify a recurring task and a real deficiency or domain need. Inspect existing skills and examples to avoid duplication. Establish what expertise requires: authoritative references, domain conventions, user preferences, constraints and evidence of successful work. If references have not been read, mark them as research needs rather than claiming their contents.

Write the smallest useful package:

- **Trigger and scope:** when to use the procedure and when it is irrelevant.
- **Inputs:** required context, where to find it, what can be inferred and which missing facts require a question.
- **Method:** ordered actions with decision points and reasons. Use exact tool names only when available; describe fallback investigation when a capability is missing.
- **Outputs:** useful artifacts and their format, units or structure.
- **Verification:** observable checks tied to the task's purpose. Explain what passing does and does not prove.
- **Recovery:** common failure signatures, diagnostic steps and stopping conditions.
- **Example:** one realistic input, the important decisions and a good result; contrast a tempting but incorrect method and explain why it fails.

Keep the main SKILL.md focused. Put long examples, domain reference tables and optional procedures in named relative resources, and say when each should be read. Put deterministic transformations in scripts only if repeated execution provides value. Do not paste the full project history or repeat the host's general policy into every skill.

Example: a literature-review skill should teach how to define a question, choose original sources, record publication context, separate evidence from inference, resolve conflicting findings and check claim-to-source coverage. “Research deeply, use high-quality sources, write professionally” gives no procedure and is not an adequate skill. A good example demonstrates why a broad press summary cannot support a precise experimental claim.

Test the procedure on a representative task and a changed scenario. Observe where instructions were misunderstood, which context was missing and whether the final artifact improved. Revise the causal weakness, not the wording merely to get a familiar answer. Preserve useful exceptions. Record limitations instead of advertising untested expertise. Domain or tool documentation embedded in a skill does not grant extra permission.
