---
name: Project analysis
description: Understand a project's purpose, constraints, structure and missing decisions from evidence.
---

Use when entering a project, clarifying a substantial request or diagnosing why current work does not satisfy the user's purpose.

Read the brief and bounded workspace orientation. Inspect the relevant source, existing deliverables and scoped project instructions; a directory listing alone does not establish implementation status. Identify the user, the primary job, constraints and the intended delivered artifact. Preserve prior decisions, and separate user intent, verified facts, assumptions and unresolved questions.

Map the request to a few recurring task families and required capabilities. For each, identify the appropriate professional method, inputs, deliverables and verification. Prefer existing tools; record concrete capability gaps without inventing integrations. Ask a focused question only when a missing decision materially changes the outcome. Infer reversible details and proceed when the authorized direction is clear.

Create milestones around usable outcomes rather than layers of implementation. Each milestone needs a representative user scenario, an acceptance check and dependencies. Work through a complete slice, observe its result, and revise the plan when evidence changes. Track what was actually verified separately from what is only implemented.

Example: “Create a game-development workbench” is a capability direction, not proof a game exists. Inspect available assets and code, establish the intended player experience, then plan a playable interaction with feedback and restart. A generated geometry helper does not by itself constitute game-development expertise. Domain references, gameplay checks and visual review may be more valuable than another helper.

For substantial deliverables, load rna-delivery-quality. For a reusable capability gap, use rna-learning-method. Keep the user-facing explanation concise and grounded in the project. Do not manufacture completed work or store a parallel local semantic memory; use the host's assigned memory service for that purpose.
