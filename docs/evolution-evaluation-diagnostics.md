# 候选评估结果与重试

版本是否值得讨论、能否通过冻结评估、能否投入试用是三个不同结论。改进建议保留在原候选中，脚本和评估失败不会删除建议，也不能据此跳过版本门槛。

这些记录没有证明裁判或基础设施异常。冻结兼容检查采用精确 JSON 契约，新增字段也可能失败；若产品需要扩展契约，应新增工具或单独审阅契约迁移，不能暗中改旧答案来通过。

## 返回契约

`project-evolution-assessment.mjs` 的 `describeEvolutionAssessment(version, { activeVersionId })` 是只读投影。旧记录按现存证据即时分类，不写回历史评分、通过门槛或状态。

返回 `category`、中文 `label/summary`、`stage/code`、`scoredCases/totalCases`、`failedChecks`、`candidateRetained`、`retry`。检查摘要只含检查类型、失败数量和工具标识，不包含用户正文、原始答案或密钥。

分类区分：候选脚本无效、冻结兼容失败、效果门槛未达到、基线自身阻塞、评估过程错误、候选生成错误、额度不足、中断、基线过期、进行中和通过。未评分时保持分数为空，不伪造 0 分。

SDK 记录失败阶段：提案、脚本修复、基线执行、候选执行或裁判。截断、空最终正文、无效结构、遗漏裁判指标属于评估未完成；实际违反必需内容、工具或禁止内容约束仍是确定性失败，不降低门槛。

## 显式重评

现有进化入口接受 `{ "retryVersionId": "原候选ID" }`。不能同时提交修改后的 `genome`。只允许已有可校验候选的评估错误、额度阻塞或中断记录重评；基线必须仍是同一版本和 hash。脚本/兼容/质量真实失败要求先修订候选，不以重复调用修复同一个错误。

重评读取已保留能力包，校验候选 hash 与冻结基线 hash，生成带 `retryOfVersionId` 的新记录，不覆盖原证据。它会重新执行所有必要检查并按实际调用计费；不是续跑或复用先前裁判结果。没有可验证候选的旧失败记录需重新生成。自主运行不会自动重放同一失败请求。

## Harness 参考边界

参考仓库的 `packages/boot/plugin-manager/README.md` 明确保留失败阶段、部分操作结果、错误分类和可恢复操作，安装成功也不等于启用成功。其扩展管理与 UI 将运行状态和历史记录分开。这些原则用于本系统的阶段诊断和不可变重试记录。

`packages/goal/goal-round-driver/README.md` 明确说明没有独立 evaluator，异常不会自动无限重试。本项目的冻结用例、真实脚本执行、匿名对照裁判是 Rna 自己的评估实现，不将其误称为 Harness 已具备的质量认证。
