# 桌面工作台、CLI与交互规格

> 历史设计稿。下面有关直接使用 Pi AgentSession/SessionManager、默认项目和部分目标接口的文字不描述当前实现。现用独立 Rna SDK，以目录确定项目；主区入口为对话、任务、版本、观察、文件。当前架构、已验证改动和未完成差距见 2026-09-27 系统审计。

平台以项目为长期协作边界，以聊天为日常工作表面。Agent 持续理解项目状态、最近对话、未闭环问题与当前环境，在值得行动时自行调查、执行或发起沟通；没有用户命令、没有显式 Goal，也可以发现变化并主动开口。用户输入可以随时插入这一过程。自主进化同样由项目经历驱动：系统自行发现能力缺口、构建版本、比较评测，在新版本值得试用时回到项目对话主动说明证据。

“主动”不是定时重放一套任务脚本，也不是每隔几秒发一句状态。Agent 需要决定做什么、是否值得做、是否应现在打扰以及何时保持安静；可见的沟通与后台执行共用项目事实与预算。Goal 是可选的长期承诺，不是主动循环的启动开关。

依据为 Pi 交互源码研究与 DeepSeek Harness 深入交互研究。Pi 的依据是 interactive TUI 及 AgentSession/SDK/RPC 的真实行为；本规格将其映射成 Web/桌面交互，不声称 Pi 上游已有对应桌面 GUI。当前[交互原型](../../prototypes/control-center/README.md)验证界面及共享控制，模型、工具和评测的模拟边界以原型说明为准，正式能力以本规格及功能清单为准。

## 1. 信息架构

```text
Rna Agent
├─ 项目工作区（默认）
│  ├─ 项目管理：切换 / 项目状态 / 成员与授权 / 主动策略 / 当前版本
│  ├─ 项目会话：新建 / 搜索 / 最近会话 / 未读主动消息
│  ├─ 当前会话：用户意图 / Agent 文本 / 工具 / 结果 / 产物
│  ├─ 常驻输入区：输入 / 附件 / 命令 / steer / follow-up / stop
│  └─ 按需资源：文件 / diff / 终端 / 浏览器 / 上下文 / 分支
├─ 项目后台：状态观察 / 开放线索 / 自主调查 / 版本评测 / 可选长期目标
└─ 管理与设置（辅助入口）
   ├─ 能力：Skills / MCP / Tools / Plugins
   ├─ 记忆：事实 / 偏好 / 经历 / 过程知识 / 冲突 / 已删除
   ├─ 进化：Campaign / Candidate / 对比 / 灰度 / 发布
   ├─ 成本与缓存：token 口径 / 预热 / 失效
   └─ 设置：模型 / 凭据 / 权限 / 后台 / 数据 / 发行更新
```

默认打开最近项目中的最近会话；首次已有默认项目，没有会话时直接提供输入框和少量使用提示。项目管理高于会话：每个项目拥有独立目录、会话、记忆、能力版本、候选、预算和主动策略；跨项目切换不把另一个项目的消息、草稿、评测或版本注入当前上下文。第一次输入建立 session，并从原文生成可修改标题，不要求先填写任务标题、说明、预算表单。预算有工作区默认值，可在需要时调整。管理入口不占据默认正文。数据需要显示 `真实 / 模拟 / 未连接 / 未测量`，不能把示例命中率当成真实服务状态。

### 对象及边界

| 对象 | 定义 | 界面对应 |
|---|---|---|
| Project | 长期协作、授权、记忆、主动策略与能力版本的边界；包含多个 Session | 顶层项目选择器、项目摘要、版本与主动状态 |
| Session | 项目内的持续会话、历史分支和上下文；由 Pi SessionManager/AgentSession 管理 | 左栏条目、标题、完整 transcript、草稿、分支 |
| Turn | 产品层的一次交流或主动行动，可由用户、项目观察或进化事件触发；Pi 底层 `turn_start/end` 须单独映射 | 用户输入（若有）、Agent 段落、工具步骤与结果；主动回合没有虚构 user 消息 |
| Step | 一项可观察动作，例如一个工具调用、一次验证或扩展交互 | 内联卡片及可展开证据；以稳定 ID 关联 |
| Run | daemon 调度的一次执行尝试，可跨多个 Pi turn，归属于一个 session，可关联 goal | 正在生成、工具执行、压缩、重试、等待输入及结束状态 |
| Goal | 可选、可跨 session/run 和多次唤醒的明确长期承诺，具有验收条件、范围与预算 | 后台工作入口与会话内的目标卡 |
| Observation / OpenLoop | 带来源、时效、去重键的项目状态变化，以及尚未闭环的疑问/机会 | 主动消息的“为何现在提出”证据、项目侧栏摘要 |
| Candidate / Release | 项目内隔离生成的能力变更与评测通过后的固定版本 | 对话中的版本通知、对比/试用/回滚卡 |

层级为 `Project → Session → Turn/Step`；自主控制为 `Project → Observation/OpenLoop → Decision → Run/Message/Silence`，Goal 可以关联其中某些动作。不要把 `Session = Task = Run` 合并。一个会话可以有多次执行；一个 goal 可以跨多次执行。对 Pi 而言 `message_end` 是消息定稿，`agent_end` 是一次底层 loop 结束，`agent_settled` 表示当前暂时不会自动继续。`agent_settled` 不是持久化 ACK、不是外部副作用提交记录，也不是长期目标验收通过。命令接受、事件落盘、工具副作用和目标验收分别有自己的状态。

## 2. 会话主表面与按需资源

```text
┌ 项目与会话 ──────┬ 当前会话标题 / 项目 / 分支 ──────── 资源入口 ┐
│ 新会话、搜索      │ 用户意图                                     │
│                  │ Agent 文本                                   │
│ 最近会话         │ ├─ read / bash / edit 工具卡                  │
│  · 正在工作      │ ├─ 原位选择、输入或权限决定                    │
│  · 等待输入      │ └─ 结果、文件与可检查的验证                     │
│  · 最近完成      │                                              │
│                  │ 当前运行状态 / 待处理 steering 与 follow-up    │
│ 后台工作         │ 常驻输入框：附件、命令、草稿                    │
│ 管理与设置       │ model / scope / context / cost / stop        │
└─────────────────┴──────────────────────────────────────────────┘
                    点击文件、diff、终端、上下文时才打开侧面资源
```

两栏是默认状态。资源打开时可形成三栏，但资源区域没有内容时不保留空白列，也不强制用户在“聊天/日志/计划”页签间切换才能看懂正在进行的工作。建议桌面默认1280×820，左栏220–260，资源区按内容在320–480间调整；中央保持可读文本宽度。低于1000px资源变为覆盖抽屉，低于720px会话导航收起，composer 保持可达。手机用于查看与基本控制，不承诺完整终端编辑体验。中英文、长路径和多行错误必须可换行/展开。

### 回合与工具的投影

主 transcript 按实际发生顺序呈现用户与 Agent 交流、工具步骤和结果，不强制每段助手内容前必须有用户消息。主动发起的回合带轻量“主动发现 / 后台结果 / 版本可试用”来源标记和可展开证据，正文仍是自然对话；steering 被消费时在真实位置加入用户输入。工具参数生成、执行开始、增量结果、结束分别更新同一卡片。`toolCallId` 是关联依据，不能每个流式事件都追加新卡。原始事件留在诊断视图，普通用户不需要读取 JSON 才知道发生了什么。需要 provider 支持的公开推理内容才单独呈现，不把不存在的内部推理补写成“思考流”。

工具卡统一包含：工具与来源、动作与参数摘要、生成参数/执行中/完成/失败/中止状态、耗时、输出、错误/重试、产物、对应授权与副作用状态。read 显示路径与范围，bash 显示命令及退出码，edit 显示 diff，搜索显示范围与命中项；未知工具使用通用 renderer。长输出提供短预览、展开、搜索及 artifact，不挤走后续结论。完成卡区分“执行成功”和“验收通过”；退出0不自动等于完成目标。

skill invocation、compaction summary、branch summary、扩展交互都是独立有类型的内容。调用 skill 后可查看来源及实际版本；压缩展示发生时间与摘要入口；请求用户选择/输入时在对应位置出现交互卡，不追加一个无关联审批后台任务。扩展 `requestId` 用于提交/取消并显示已回答状态；通知与状态更新不制造待处理批准。

文件与产物卡位于产生它们的回合，点击打开侧面预览并保持会话阅读位置。资源通过 session/run/step/artifact ID 关联，关闭面板只关闭视图，不终止对应工具或删除文件。资源面板可以接收插件贡献，但具有独立的注册、卸载和内容生命周期。

### 常驻 composer 状态矩阵

| 运行状态 | Enter / 主动作 | Alt+Enter / 次动作 | Stop / Esc | 可见状态 |
|---|---|---|---|---|
| Idle | 发送并开始新 run | 与发送相同 | 无当前运行可中止 | model、scope、附件、命令提示 |
| 生成文本/工具参数 | 下一步调整：`steer` | 完成后追加：`followUp` | abort 当前运行 | 编辑器保持可用、两种队列分开 |
| 工具执行中 | 在当前工具批结束后、下一次模型请求前消费 steer | 等当前 run 的工具与 steer 结束后消费 | 发送 abort 并等实际停止 | 显示工具动作及中止中状态 |
| Compaction / branch summary | 宿主暂存输入并保留 mode | 暂存 follow-up | 取消压缩或摘要 | 不锁定编辑器；展示待发队列 |
| 自动重试 | 仍由当前 run 管理输入和队列 | 保留 follow-up 模式 | abort retry | 等待原因、尝试次数、可取消 |
| 主动调查/进化检查 | 用户输入优先，进入下个安全边界并重新判断后台工作 | 明确选择 follow-up 才排在当前行动后 | 停止本轮，不等同关闭项目主动能力 | 标明自主动作来源、可继续输入 |
| 有主动消息待交付且正在输入 | 正常发送；先消费用户新事实，再重评待发消息 | 与当前运行的 follow-up 规则一致 | 可静音项目主动通知 | 不覆盖草稿、不移动焦点，低优先消息延后 |
| 等待扩展输入 | 对指定 request 作答；自由文本不能误当响应 | 可保留普通草稿 | 取消对应交互 | 待回答卡固定可发现 |
| 已中止/失败 | 在原 session 继续或从历史分支 | Idle 时等同发送 | 无需结束整个 session | 保留局部输出及结束原因 |
| 断线 | 草稿可编辑；不得假装服务端已接收 | 不把离线草稿伪装成服务端队列 | 显示未送达与重连状态 | 重连后对账，避免重复执行 |

`steer` 不是立即杀死工具：Pi 在当前 assistant turn 的工具批结束后、下一次模型请求前消费它。follow-up 等待当前工作没有剩余工具与 steering 后再进入。按钮文字和快捷键必须表达这一区别。停止使用 `AgentSession.abort()`；以实际 idle/settled 状态更新，不只把本地 spinner 隐藏。

待处理条目显示原文、类型、接受状态，未消费前留在队列区；消费后在 transcript 的对应位置出现一次。支持取回编辑；已消费条目不能再伪装可撤回。停止时恢复未消费内容并保留当前草稿，不无声丢弃。可选逐条移除必须由 daemon 验证消费边界。Pi TUI 当前是聚合取回全部队列，Rna Agent 提供逐条编辑属于宿主扩展能力。

草稿按 session 保存，流式重渲染、会话切换和网络失败均不覆盖新输入。中文输入法 composition 期间 Enter 不发送。滚动历史时不强制跟随新增文本，提供“回到最新”入口；停留底部才自动跟随。工具展开状态、文本选择和当前焦点在增量更新时保留。

暂停长期调度是 Rna Agent 的语义：在安全边界阻止继续，先显示“暂停中”。Pi abort 终止当前操作，不是进程快照暂停，不可宣称能从任意指令原位恢复。取消不可撤回的外部动作需显示真实状态；当前运行 Stop 始终可达，全局急停在后台控制入口可直接触发且不依赖模型回复。

### 历史、分支与上下文

会话标题提供历史/分支入口，用户消息提供“从这里继续/另开分支”。Pi `/tree` 改变同一 session 的 active leaf 并保留旧分支，`/fork` 建新 session，`/clone` 复制当前 active branch；三者明确区分。选择历史 user message 时回填原文，编辑后形成新分支；可选择携带离开分支的摘要。切换分支改变模型上下文，不自动撤销已发生的文件或外部副作用。

model、thinking level、当前能力范围、context、费用与连接状态位于 composer 附近。点击打开当前 session 的详细上下文、cache 读写与来源；压缩后的 context 在下一次模型响应前可能未知，应展示未知而不是编造精确 token。`/compact`、`/model`、`/skill:name` 与模板/扩展命令通过 composer 菜单发现，展示其来源和种类。输入补全是能力使用入口，安装页不是唯一入口。

### CLI 与桌面的共同会话

主运行通过 daemon 内的 Pi `AgentSession` 与 runtime host，UI/TUI/CLI 连接同一 session 的命令与事件投影。界面不另建 LLM loop，也不自行修改 `agent.state.messages` 冒充持久会话。session/runtime 替换后重绑订阅；每个事件携带目标身份，旧会话的延迟帧不进入新会话。

使用 RPC 时保留协议能力边界：本次版本有 `get_tree`，没有同 session 的 `navigate_tree` 写命令；同会话树导航由 SDK host 暴露宿主 API。RPC extension dialog 可适配 Web，但 TUI 自定义组件、footer/editor renderer 不能直接嵌入浏览器。`agent_settled` 仅作为运行不再自动续行的信号，daemon 的 accepted/persisted ACK、幂等 request ID 和重连序号另行定义。

## 3. 融入对话的项目主动性

状态模型、决策协议和后台运行契约见[项目主动系统规格](project-proactive-system.md)；本节定义其用户可感知的交互。

### 持续感知与自主决策

项目启用主动协作后，观察器接收已授权的仓库/文件变化、工具结果、依赖就绪、评测结束及对话承诺。调度器以事件唤醒为主，配合有上限的反思检查、退避与静默期。决策使用项目状态、相关对话摘要、开放线索、用户当前关注和资源余额，可以选择：安静更新事实、只读调查、执行已有授权范围内的工作、向用户提出有价值的问题、交付后台结果或暂不行动。没有 Goal 不妨碍上述过程；没有新证据和有价值线索时不生成无意义回合。

交互借鉴 Headlong 的持续运行、面向用户与后台思考分工，但产品不暴露一个机械心跳列表作为主体验。每次主动行动记录观察证据、决策类型、预算、会话归属与幂等键；诊断面板可检查因果，正文优先说明发现、影响与下一步。模型的决策理由可用公开摘要呈现，不展示或伪造内部思维链。

例如用户前一轮讨论了发布兼容性，随后依赖版本变化。Agent 可自行检查影响，在同一项目会话说：“刚才提到的依赖有了新版本。我检查到一处接口变化，现有测试没有覆盖；我已准备兼容性测试，可以先看看结果。”这段交流不需要用户先创建“监视依赖” Goal，但执行必须落在项目已启用的观察范围、工作范围与预算内。

### 注意力、插话与节奏

前台对话具有最高调度优先级。用户正在输入、窗口处于组合输入或有未提交草稿时，低优先主动消息进入待交付区；继续后台可逆工作与打断用户是两个独立决定。停止输入一段可配置间隔后可以交付；新用户消息到来时先重新检查相关性，合并重复消息或丢弃过时建议。不能仅靠一次前端 `typing=false` 永久保证无人输入：多客户端 presence 有时效，断线过期，最终交付有服务端判断。

用户在自主调查或工具执行中发送消息，沿用 steer/follow-up 的真实边界；不强制停掉整个项目的主动能力。停止当前回合、暂停某条开放线索、静音通知、暂停项目自主执行、全局急停是不同控制。静音可以保留授权的后台工作；关闭项目主动执行则不再领取新的自主工作。静音（暂停主动发言）同时暂停定时任务：到点的执行记为跳过、每个日程只留最近一次，已认领但还没开始的也不开始；解除静音后只补跑仍在一个周期内的最近一次，不补积压（静音期间日程被关了又开就不补跑）；静音前已开始的执行做完后结果只放进收件箱，不贴进对话；等待交付超过一个周期的结果只放进收件箱，不在对话里补发。不急的主动发现在静音期间照常安静送达（不提醒）。设置页、日程列表与模型看到的 REACH 指导用同一说法。工具已发生的副作用不因为插话而被描述为撤销。

主动消息必须对当前项目有用：说明为什么现在提出、已做什么、还缺什么，只在需要决策时带动作按钮。同一根因通知合并；无变化不重复催促；用户拒绝或推迟会更新关注与冷却策略。关键失败可以使用事先配置的高优先通道，但不能把普通版本候选都升级成紧急打断。

### 项目管理在会话之上

顶层项目选择器始终可达，项目摘要显示目录、近期变化、开放线索、主动状态、当前稳定版本和试用版本。点击才打开项目管理抽屉；默认正文仍是最近对话，不变成项目 KPI 看板。新项目可先聊天，再逐渐获得记忆与能力；默认项目保证初次使用不先填写复杂配置表。

项目策略包含可观察目录/事件、允许的自动动作、反思预算、进化预算、静默时间、通知偏好和版本试用范围。每次 run 固定项目 ID、权限快照及版本 manifest，切换项目只改变浏览对象，不把后台工作归属改写为当前选中项目。非当前项目的新消息以该项目未读标记提示，不插入眼前会话。

### Goal 的保留位置

用户可以把一项意图提升为明确长期 Goal，配置验收标准、期限和预算；这增加一个持续承诺，不是给项目“通电”。Goal 的暂停、恢复、取消仅作用于关联工作；项目仍可处理其他事件并沟通。原型中此前的七步 Goal 演示保留作定时/事件调度回归，它只验证固定场景，不再作为平台主动能力的主入口或证据。

### 当前原型与正式能力的边界

当前演示通过确定性策略和模拟观察/工具结果呈现项目主动行为；调度、持久化、输入注意力、项目隔离和版本切换可由本地程序真实验证。它不表示已经接入会理解状态的模型、真实仓库观察器、Pi 工具执行或独立隐藏评测。界面必须把示例事件与模拟评测标清。正式产品替换决策与工具适配层后，仍需通过相同的注意力、投递、预算与版本契约；不能用演示脚本的完成率证明智能收益。

## 4. 能力管理

这些页面从管理入口按需打开。当前会话的 composer 展示实际启用能力，并可从 slash 菜单调用；“已安装”“连接可用”“当前 session 已启用”是不同状态。

### Skills

列表显示名称、来源、版本、正式/候选状态、最近验证与使用任务。详情含SKILL.md、资源、脚本、适用/不适用情形、权限、历史diff和回退。正文按需加载，避免浏览技能列表就把所有内容注入模型。

### MCP

添加连接向导选择stdio或HTTP，配置从本地安全存储读凭据；测试初始化/工具列表但不自动执行写工具。工具表显示schema、版本、来源、真实授权与状态。服务断线有重连/停用，schema变化展示受影响run，不能悄悄修改正在执行的工具。

### 插件

安装只把固定版本放入候选环境；启用前显示来源、依赖、脚本、工具及权限差异。第三方UI在隔离容器贡献受限视图；不向插件给出通用Electron IPC或provider凭据。

## 5. 记忆库

会话中展示本次相关记忆的来源提示，点击打开召回详情；全量记忆库用于搜索和治理，不占据默认主导航的工作区域。

搜索可按工作区、类型、时间、来源和状态过滤；结果展示简短内容与引用。点击后看来源证据、修订、适用范围、冲突与有效期；可纠正、限定范围、冻结或删除。

“为什么召回”展示匹配依据与被注入的版本；“删除”显示立即停止检索及后台派生清理状态。未经确认的模型推断带“待验证”，不显示百分比式伪精度置信度。不能在检索结果摘要里泄露无权查看的内容。

## 6. 项目自主进化与版本试用

自进化由项目经历持续驱动，不以用户点击“创建实验”为前提。重复失败、人工纠正、重复操作和新约束形成能力缺口；系统判断预期价值及预算后，自行开立 campaign、构建隔离候选、运行开发验证与独立评测。进化对象可以是项目 skill、工作流、工具适配或提示配置；改动运行时核心和全局权限属于独立发布范围，不能借项目候选静默改写平台自身。

候选始终归属项目，保留来源 episodes、基线 manifest、变更 diff、artifact hash、数据版本、全尝试费用与停止原因。当前执行固定旧版本，后台评测不热替换它。候选无法修改评测器或取得隐藏题目；评测失败、回归或证据不足时自动保留失败记录并继续使用稳定版本，而非总是产生“升级成功”。

当候选在约定质量、回归、费用和权限门槛上优于基线时，系统自行在关联项目对话沟通，例如：“我根据最近三次兼容性检查改进了项目技能。新版本通过了独立确认集，旧任务未见回归；可以对下一轮开启试用，或先看差异。”通知携带证据入口和候选 ID，受输入注意力、合并去重与冷却规则约束。是否把试用自动化由项目已授权发布策略决定；默认通知用户可试用，不把生成/评测的自主性变成每一步都需要点击批准。

对话卡提供“查看差异与证据”“试用新版本”“稍后提醒”；试用后显示当前试用范围、基线和“回滚”。版本动作由 daemon 校验项目与候选归属、gate 状态、hash 及并发 revision。试用只影响之后开始的 run；回滚只切换版本指针和后续运行，不能声称撤销已经发生的文件修改。试用期间发现退化可以按已配置门槛自动回退，并在同一对话解释原因。

进化实验室为次级证据面板，展示已发现/构建中/评测中/被拒绝/可试用/试用中/已保留/已回退。表格展示原始分数、基线差值、不确定性、任务族回归、成本与权限变化。未经独立评测的候选标明实验性；模拟样例不能显示成真实质量提升，MVP 少量项目样本也不能外推为普遍能力提高。

## 7. 成本与缓存

会话底部显示本 session 的紧凑摘要；本页是可展开的详细诊断与全局核算，不能替代主会话表面。

默认显示已结算、在途预留与限额。按任务/目标/模型/后台/进化分类；供应商token明细保持口径说明。缓存页含可比输入总量、读/写cache token、预热次数、时延、实际收益区间，未提供的字段标记NA；用量页不显示价格或费用（后端不跟踪真实价格，用户 2026-10-05 决定）。

缓存诊断展示本次请求与上次的结构差异：系统段、工具schema、模型、压缩/上下文窗口、TTL和请求序列。用户可关闭预热、减少主动预算，不直接暴露难以解释的供应商内部参数作为默认产品开关。

## 8. CLI命令设计

以下是正式产品命令提案；演示原型实际使用 `node cli.mjs`，不与此混淆。

```sh
rna init
rna                              # 打开当前工作区的会话客户端
rna projects list
rna project use project_123
rna project inspect project_123
rna project proactive project_123 --mode enabled
rna project quiet project_123 --until tomorrow
rna sessions list --project project_123
rna session new --workspace .
rna attach session_123
rna send session_123 --message "继续检查过期 token"
rna send session_123 --mode steer --message "先验证兼容性"
rna send session_123 --mode follow-up --message "完成后补迁移说明"
rna session stop session_123
rna session queue session_123
rna session dequeue session_123
rna session fork session_123 --entry entry_123
rna session tree session_123
rna session compact session_123
rna run "修复这个测试" --workspace . --budget 5 --json
rna runs list --state running
rna attach --run run_123
rna run pause run_123
rna run resume run_123
rna run cancel run_123
rna run steer run_123 --message "优先验证兼容性"
rna goal add --file goal.yaml
rna goal enable goal_123 --autonomy bounded
rna daemon status
rna desktop
rna skills list
rna skills diff candidate_123
rna mcp add --file mcp.json
rna mcp inspect connector_123
rna memory search "部署流程" --workspace .
rna evolution status --project project_123
rna evolution propose --project project_123 --surface skill # 可选人工触发，日常自动发现
rna evolution evaluate candidate_123
rna evolution trial candidate_123 --project project_123
rna evolution promote candidate_123
rna evolution rollback release_123
rna costs --goal goal_123 --json
rna doctor
rna stop --all
```

参数中的budget为示例额度，真实调用需用户配置且生效前显示币种。自动化脚本使用 `--request-id` 幂等调用；CLI输出分stdout结果与stderr诊断，流式JSON逐行事件。退出码建议0成功/请求被接受、1执行失败、2参数错误、3等待用户、4预算耗尽、5连接/认证错误；异步create成功不等于任务已完成。

TUI可基于pi-tui构建客户端，不能直接另起一个绕过daemon的Pi会话。需要离线独立模式时另行显式选择，独立模式不写daemon当前拥有的session。

## 9. 桌面生命周期与发行

Electron启动时发现兼容daemon；没有则从固定runtime包启动并完成认证握手。独立daemon由用户可管理的服务拥有，防止桌面升级导致所有长期任务退出。窗口关闭默认允许已授权任务继续，并在托盘显示状态；“退出并停止后台”是不同动作。

首启建立或选择项目、配置模型、设置预算、启用项目主动策略、能力安装/授权及测试任务；密钥送到系统keychain，不写前端localStorage。首次需要沙箱/辅助功能/屏幕录制权限时说明对应工具用途，不在启动时一次性索取全部系统权限。

更新先暂停新任务调度、等待安全边界或按策略处理在途任务；迁移/回滚流程见存储规格。Windows/Linux与macOS在后台服务、路径、进程树、权限和签名上分别验收。

## 10. 无障碍与交互验收

所有操作有可见文字或可访问名称；键盘可访问任务、tab、审批、输入与急停；状态不只依赖颜色；遵循减少动态效果偏好。长任务不用无限spinner代替明确等待原因。错误、离线、空列表、权限拒绝、预算耗尽都设计独立状态。

验收场景：无需创建 Goal，项目新事实能触发一次有证据的主动调查/沟通；无新事实时安静退避；输入中延后普通主动消息并保留草稿，插话后重新判断待发内容；自主生成候选、评测拒绝坏版本、对更优版本主动提示试用、试用与回滚只影响所属项目的新 run；切项目不串会话/预算/记忆/通知/候选；CLI创建/UI控制同一 session；连续输入保留上下文；运行中 steer 与 follow-up 按各自边界消费；停止后待发输入与草稿可恢复；工具卡从参数到结果更新而不重复；`message_end` 不提前标完成；压缩和重试期间输入可用；分支保留旧历史但不宣称文件回滚；两个窗口并发动作冲突；断网重连保留草稿并对账；10,000条事件滚动仍可用；中文输入法组合中不误发；窄窗口不遮挡 Stop；屏幕阅读器不逐token播报；凭据不出现在DOM；不可信工具内容不会执行脚本。
