# 应用更新、恢复点与故障恢复

适用于主程序 0.15 / SDK 0.8。这里的“应用版本”与项目自己进化出的提示词、技能、工具版本分开管理。

## 日常使用

打开设置中的“应用与恢复”。选择本机 `.app` 或完整运行目录，先检查包，再选择更新。检查会完整复制 Node、SDK、宿主、UI、npm、CLI 及连接模块，校验文件摘要、架构和状态格式，在本机保存只读版本目录。检查成功只表示本地内容完整，不代表开发者签名可信或模型能力提高。

更新流程为：暂缓新任务 → 已接纳工作收尾 → 确认旧服务干净退出 → 创建并验证恢复点 → 切换运行目录 → 核对新服务身份与就绪状态 → 恢复接纳。等待期间草稿保留；可以停止当前任务，也可以取消尚未进入停机阶段的维护。服务连接中断时页面核对原请求，不重新提交更新。

若长期任务未结束，维护会继续等待，最长等待窗口结束则保留原有工作、报告本次维护未完成。不会为抢占更新而强行结束任务。需要后台托管模式；直接 `rna start` 的前台服务可检查包，但不会由更新器猜测其拥有者并停止。

```sh
./rna maintenance status
./rna maintenance prepare '/Applications/Rna Agent.app'
./rna maintenance apply <候选ID>
./rna maintenance backup
./rna maintenance rollback <曾成功使用的候选ID>
./rna maintenance cancel <仍在等待的操作ID>
```

CLI 等待超时只意味着操作还在后台处理，不是成功。使用 `maintenance status` 核对最终状态。提交结果不确定时可使用原 `--request-id` 明确重试；相同 ID 不允许用于不同请求。应用回退不会恢复旧会话数据，只有兼容当前状态格式且本实例曾成功使用过的版本才提供回退入口。

## 恢复点覆盖什么

包括主状态、独立凭据及订阅记录、SDK 会话日志、项目能力包、初始化与进化记录、已安装能力记录、归档和目录观察收件箱。服务配置和耐久观察的小型记录作为证据保留，旧进程锁、服务拥有者、维护记录、运行版本目录不会恢复为正在运行的进程。

不包含用户项目目录、远端 OpenViking 数据、全局第三方登录库。文件及目录权限分别为 `0600` / `0700`；检查点可能包含凭据，应按本机私有应用数据保管。历史检查点不会自动删除。

原路径恢复有离线排他锁、恢复前副本、隔离目录和持久事务记录。中途崩溃会阻止普通启动，使用原事务接续，不对半恢复状态运行 Agent。主状态文件损坏或丢失时也可恢复；损坏的原始副本仅用于调查，不被标为可运行恢复点。

## 数据恢复后的核查

```sh
./rna maintenance restore <恢复点ID> --confirm
./rna recovery status
./rna recovery resume <中断维护的操作ID>
./rna recovery reconcile <已还原的操作ID> --confirm
```

主程序无法启动时，指定原状态文件使用离线入口：

```sh
RNA_AGENT_STATE='/原路径/state.json' ./rna recovery status
RNA_AGENT_STATE='/原路径/state.json' ./rna recovery restore <恢复点ID> --confirm
```

还原后的本机日志可能比项目文件、已发送请求或远端记忆更旧。先核对恢复点之后发生的工作，再执行 `reconcile`。核查会保留恢复前证据，把旧会话标为历史、旧待办标为需核查，并暂停主动协作、进化、日程、记忆自动写入。重新打开工作台后，解除急停并新建会话开展新工作；不要把核查成功理解为已撤销过去的外部效果。

核查后可以在设置中重新开启新会话的自动记忆。恢复前的会话、写入和未确认的摘要任务仍隔离，开关不会重放它们；关闭自动保存时产生的对话也不会因重新开启而被补传。当前没有自动对账并重放全部旧提交的通用工具，不能宣称已无损恢复过去的外部效果。原会话 `rna recovery <会话ID>` 的工具核对命令仍保持兼容，与以上应用恢复入口分开。

## 发行边界

当前验收覆盖本机 macOS arm64 安装、真实后台进程切换、CLI 与 GUI、故障恢复及本地完整性。0.14 及更早包没有新维护协议，仅可导入作为历史基线，不能自动认定其可安全回退。没有在线更新源、发行者签名验证、Apple Developer ID 签名、公证或 Intel / 其他平台发布资格；ad-hoc 签名不能替代这些条件。
