# 进化 v3：基因树（2026-09-30）

取代 `proactive-evolution-v2` 第 4 节与 `evolution-and-evaluation` 规格中的候选-评测流程。目标：自进化从"整包重写 + 合成评测"改为"一次一个基因 + 真实工作验证"，用户只看到一棵树和每个节点的一句话。

## 0. 为什么重做（线上数据，2026-09-30）

| 事实 | 数字 |
|---|---|
| 整包候选从未被采用 | 3 个项目 37 个候选、约 1140 万 token，0 采用；小说项目的 `project-workflow` 技能至今 169 字 |
| 经验只做上下文，不变成机制 | 小说项目 8 条经验：「不得复用『守夜人』」应用 0 次；「每日 1 万字」被违反 6 次 |
| 评测不是用户的真实工作 | 每个项目 4 条合成问答用例；游戏项目的视觉问题只能在问答上打分（0.78→0.74 判退步） |
| 学习被自己的保护机制杀死 | 111 次复盘 100% 因"作用域哈希变化"作废 |
| 界面摊开内部结构 | 版本、评测证据、RRSI 前沿、组件、信号、失败分类六个面板，没有一个回答"它学到了什么、有没有用" |

ModularRSI 给出的可迁移做法：把 harness 拆成**独立可进化的模块**，用**成功/失败轨迹对照**找问题，只做**小范围改动**，过**程序检查 → 差异复审 → 执行验证**三道门，档案记录每个变体的父代、针对的症状和状态。我们的差异：对象是一个项目的 Agent，不是基准测试；证据是用户的真实反馈和工作，不是任务通过率。

## 1. 原则

1. **一次改一个基因**：每次进化改动一个可命名的单元（一条约束、一段技能说明、一个检查工具），2 万 token 以内，可单独撤回。
2. **知识要变成机制**：能用程序检查的约束变成守卫（自动检查）；能写进做法的偏好变成技能文本；反复出现的习惯变成流程步骤。经验只是最弱的形态。
3. **用真实工作验证**：程序检查、JEV 差异复审、在真实项目文件上执行、在用试用（用了几次没被纠正才算数）。合成配对评测不再是默认路径。
4. **用户只看到树和一句话**：没有分数、哈希、组件键；每个节点一句人话，点开才有细节；能做的动作只有"对 / 记错了 / 不再用"。
5. **和主动沟通共用一条管道**：新基因由叙述者一句话告知，确认走输入框上方的邀请；进化页只用来看。

## 2. 模型

**基因（gene）**：`{ id, layer, key, title, summary, level, status, origin, evidence[], body, generation, history[] }`

| 层（strand） | 内容 | body | 来源 |
|---|---|---|---|
| 画像 `profile` | 偏好、约束、易错点、好做法 | 心智经验（保留现有 lessons，作为画像层读出） | 反馈、纠正、回答 |
| 提示 `prompt` | 项目说明文件的一个段落：项目根目录的 `AGENTS.md`（默认）或 `CLAUDE.md`（导入的 Claude 项目），文件名不分大小写；没有时用能力包里的初始提示 | 段落文本（进化直接改这个文件，其他代理也读它） | 复盘、对照分析 |
| 技能 `skill` | 一个技能及其说明的修订 | SKILL.md 补丁（段落级） | 反馈、复盘 |
| 工具 `tool` | 受限脚本工具 | 脚本 + 参数 + 冒烟用例 | 复盘、对照分析 |
| 守卫 `guard` | 带触发条件的检查工具 | 工具 + `trigger.onWrite` 通配 + 报告方式 | 反馈中可机械检查的约束 |
| 标准 `standard` | 项目的验收标准一条 | 描述 + 关联检查（守卫 / JEV 问题 / 回放） | 反馈、守卫、目标操作化 |

- `status`：`proposed → testing → trial → active → retired`，或 `rejected`。
- `level`：0–5。升级：用户确认或 👍（+1）、连续几次使用无纠正（+1）、守卫抓到真实问题（+1）；降级：同一话题被纠正（−1）；用户"不再用"直接退役。节点大小 = 等级。
- **代（generation）**：一次提交的基因变更集 → 一个不可变版本（沿用 `ProjectGenomeStore`，文件哈希校验）。`project.evolution.generations[] = { n, at, geneIds, versionId, summary, trigger }`。当前版本 = 最新一代。撤回一个基因 = 生成新一代去掉它，不回滚整包。

项目说明文件按 pi 的做法作为系统提示里带标签的 `project_instructions` 块进入模型，只读根目录那一个文件（`AGENTS.override.md` → `AGENTS.md` → `CLAUDE.md`，任意大小写），不读工作区其他材料；进化的提示层写回这个文件，没有时新建 `AGENTS.md`。

可执行真相仍是基因组包（`systemPrompt / skills / tools / evaluationSuite`）；基因登记表是它之上的人类可读索引（标题、摘要、等级、来源、历史），随每一代从包差异重建对齐。守卫的触发条件保存在基因记录里，由宿主执行。

## 3. 三条进化通道

| 通道 | 何时 | 做什么 | 成本 |
|---|---|---|---|
| **A 即时** | 一条持久的反馈/纠正被记下（`feedback.signal` 或回合捕获） | JEV `gene.route` 判定：可机械检查 → 守卫 + 技能备注；改变做法 → 技能补丁；否则只留画像 | 一次小作者调用，3–8k token |
| **B 回合复盘** | 一轮出现纠正、重试、工具失败 | 快速模型短复盘，最多提一个技能/提示补丁，附触发条件、预期、回溯核对 | ≤4k token，同一假设不重复 |
| **C 周期对照** | 证据累计到阈值或每周 | 成功轮次 vs 被纠正轮次按任务类型对照（ModularRSI），发现聚类后每层最多两个提议；同时提议退役从未起作用的基因、合并臃肿技能 | 一次分析调用 |

四道门，先便宜后贵：

1. **程序检查**：模式校验；工具/守卫编译并在临时目录跑冒烟用例（现有 `smokeProjectGenome`）；文本补丁的大小与禁区。
2. **差异复审**（JEV `gene.review`）：是否针对来源问题；是否只改一个基因；与现有基因是否冲突；给用户看的一句话是否属实。
3. **真实执行**（守卫）：对项目里匹配触发条件的现有文件跑一遍。命中 0 → 直接生效；命中若干 → 试用并邀请"现有文件里发现 N 处，要处理吗"；异常/超时 → 拒绝。
4. **在用试用**：基因立即进入运行时（新一代版本），等级 0；使用 K=3 次无同题纠正 → 生效升 1 级；出现同题纠正 → 退役并生成新一代。

采用从不需要用户点"采用"；用户可在任何时候从树或邀请里"记错了 / 不再用"。旧的配对评测保留为可选深检（整技能替换这类大改动），默认不跑。

## 4. 用户看到什么

- **进化页**：一棵树。中心是项目（第 N 代），五条链伸出去（画像 / 提示 / 技能 / 工具与守卫 / 标准），基因是链上的节点：大小 = 等级，实心 = 生效，呼吸光环 = 试用中，虚线 = 提议中，褪色 = 退役。新一代形成时中心有一次"裂变"动画。
- **顶部一句话**：「第 7 代 · 最近：新增检查『正文不得出现"守夜"字样』」。
- **点节点**：右侧一栏，一句话摘要、它改了什么、为什么（引用你当时的话）、用了几次、抓到过什么；动作只有"对 / 记错了（改一句）/ 不再用"。
- **对话里**：新基因生效时叙述者说一句（走现有主动消息价值判断）；守卫命中时模型在同一轮里自己修，回复里只说结果。
- **其他一切**（版本列表、评测记录、判断账本）进"详细记录"，默认折叠。

## 5. 与主动沟通的分工

- 进化不发问；需要用户的只有两种邀请：确认一条画像基因（已有）、"守卫在现有文件里发现 N 处，处理吗"。
- 叙述者一句话只在基因真正生效时说，并复用 `message.value` 判断是否值得说。
- 后台唤醒不再有独立的"学习"动作；通道 B、C 由回合结束和证据阈值驱动。

## 6. 实施

| 阶段 | 内容 |
|---|---|
| **1（本次）** | 基因登记表与代提交；通道 A 端到端（反馈 → 守卫 + 技能备注 → 四道门 → 新一代 → 写文件后自动检查）；`gene.route`、`gene.review`；进化页（树 + 节点详情 + 动作）替代版本/进化/学到的/观察四页；停用旧学习控制器与 RRSI 通道 |
| **2** | 通道 B；使用计数与升降级；标准层与检查关联；退役的自动提议 |
| **3** | 通道 C 对照分析与合并；可选深检；系统级问题记录并入同一棵树的"系统"链 |

保留不动：`ProjectGenomeStore`（不可变版本）、受限脚本运行器、技能市场接入、JEV 内核、项目心智。删除：学习控制器及其作用域/撤销机制、整包提案器路径的调度、RRSI 项目通道、旧进化四页。

## 7. 进度（2026-09-30，版本 0.35.0 / SDK 0.30.0）

阶段 1 完成：

- 基因登记表与代提交（`project-genes.mjs`）：树的读取、守卫触发匹配、一次一代的版本提交（沿用不可变能力包）、守卫停用。
- 通道 A（`gene-evolution-service.mjs`）：持久经验 → JEV `gene.route` → 模型按契约写守卫 → 冒烟（违规样本必命中、合规样本必不误报）→ JEV `gene.review` → 对现有文件试跑 → 新一代 → 对话里一句话告知；现有文件有命中的守卫进入试用并列出命中。
- 写文件后自动检查：`project_write` / `project_edit` 成功后，匹配触发条件的守卫运行，命中附在工具结果里，模型同一轮内处理。
- 项目说明文件：根目录 `AGENTS.override.md` / `AGENTS.md` / `CLAUDE.md`（任意大小写）按 pi 的做法作为带标签的 `project_instructions` 块进入系统提示，不再重复出现在工作区概览里；树的提示层显示它的段落。
- 进化页替代版本 / 进化 / 学到的 / 观察四页：树 + 节点详情 + 对 / 记错了 / 不再用 + 折叠的详细记录。旧学习控制器不再启动。

0.42.0（线上核对后修正）：通道 C 的技能补丁此前全被 `gene.review` 拒绝——模型写的回合编号（t3、3）与 T3 对不上时，"来源"退成了补丁自己的摘要；现在编号宽松对齐，仍对不上就用这次分析里用户的纠正与失败原话作来源。0.38.0 之前生成、在现有文件里有命中的检查，从没问过"要我改掉吗"；进化空闲时会对它们重跑一遍当前文件，仍有命中才在输入框上方问一次。

0.45.0（进化自 0.35 上线后停摆的修复）：线上三个项目的全部基因都在 09-29 21:35–21:37 生成，之后再无新一代。判断账本显示三条通道各自被卡住：
- 通道 A：`gene.route` 判为"改变做法"的经验（大多数）只记了一笔就停在画像层——设计里的"改变做法 → 技能补丁"从未实现。现在这类经验由作者写成一条技能补丁，走同样的门后成为试用中的新一代；之前已判过但没写成的经验补做一次（不再重新判断）；守卫写不出来或被拒、且判为改变做法的，改写技能补丁。
- 通道 B：`turn.review` 的"现有做法是否已覆盖"把画像里的经验也算作覆盖——而这次纠正本身刚被记成一条经验，于是总被判为"已覆盖"。现在只把生效中的守卫和技能补丁算作覆盖。
- 复审：被 `gene.review` 否决的补丁，把否决理由（没对准问题 / 越界 / 与已有规则冲突 / 摘要不实）交回作者改写一次，再过同样的复审；仍不过才放弃。作者与对照分析都被明确要求不得与用户已有规则冲突（对照分析此前看不到用户的经验，游戏项目那条"必须在真实浏览器核验"就与"不要进入浏览器验证"冲突而被否决）。

0.45.1：0.45.0 上线后游戏项目立即长出新一代（「音乐贴合场地主题」，试用中）；小说项目的补丁复审改写后通过，却在提交时失败——作者把规则写进了从技能市场导入的技能，导入技能的内容受来源哈希校验，改一个字节就提交失败。现在进化只把导入技能之外的项目自有技能交给作者，模型点名导入技能时改写进项目主技能；只因提交失败而没写成的经验再试一次。

0.45.2（SDK 0.34.3）：小说项目补做的 8 条做法全被复审否决。判断账本里除了一次（冲突 0.83，确属冲突）以外都是"拿不准"：范围 0.73、对准问题 0.74、冲突 0.30/0.35——旧的合并规则要求每一项都"很确定没问题"才放行。按设计第四道门（真实使用中试用：同题纠正即退役，用户随时可"不再用"）才是验证不确定改动的地方，所以复审改为只拦很确定的问题（很确定没对准、很确定越界、很确定冲突或重复、摘要很确定不实），拿不准的进试用。旧规则下因拿不准被否决的经验再试一次。
