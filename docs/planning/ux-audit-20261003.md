# 用户体验细节审查（2026-10-03）

9 个角度并行审查（只能用一次的界面、内部文本外露、静默失败、对话时间线、计数与徽标、跳转、设置与表单、中英文一致、线上数据异常），每个角度的发现由另一个代理反向核实，再加一轮完整性审查。报出 106 条，核实确认 91 条（15 条误报剔除），完整性审查补充 8 条（C1–C8，修复时先复核）。去重合并后为下面 73 项。原始发现（含复现步骤与修复思路）编号 F1–F91、C1–C8。

修复按"互不重叠的文件"分为 11 组并行进行；每项注明所属组。

## 一、输入框与草稿（组 composer）
1. 点建议卡片发送后，输入框又被同一段文字填满，再按 Enter 会重复发送（F1）
2. 新会话发出的第一条消息，下次点「新会话」又出现在输入框里（F2）
3. 新会话附的文件在会话创建瞬间被清空；首次上传失败后附件消失，重发时不带文件（F7、F23）
4. 停止时队列消息被取走，提示「已取回草稿」，但草稿是空的（F30）

## 结果（0.59.0 / SDK 0.48.0）

73 项全部修复，每项都有测试覆盖（宿主 `test/ux-*.test.mjs`、SDK `test/ux-background.test.mjs`、网页 `ux-*.spec.ts`）。第一轮修复后，评审发现的问题和组间交接做了第二轮（6 组 + 3 名评审），剩余 12 处由主线处理。

以下细节有意未做或只做了一部分：
- 第 7 项：新建会话时不清除"上次打开的会话"记录（`selectSession(null)` 也用于新会话，清掉会改变每次新会话后的启动行为）；启动时跳过已归档会话已做。
- 第 18、23 项：旧版迁移提示、演示执行器文案、请求格式类报错（如"请完成或停止当前轮次后再整理上下文"、参数格式不正确）仍只有中文：不属于对话失败或恢复提示。
- 第 30 项：没有重新校准 mind.judge 的"已解决"门槛（AGENTS.md 要求先做标注探测）；turn.settled 结论没有另存到轮次上（判断服务只返回合并结论，等它返回分项结论后再做）。同一条消息既是长期规则又含一次性请求时，一次性部分不单独追踪（需要新的 JEV 问题和探测）；这一轮本身失败或停止时仍会记录。
- 第 31 项：没有按关键词过滤 Agent 承诺里的"过程说明"（属启发式规则）；只加了结构检查（以冒号结尾的引导句不算承诺）。
- 第 35、39 项：没有做"查看即确认"和"长时间未更新的正在做标成已搁置"（前者让查看产生写操作，后者需要没有依据的时间阈值）。
- 第 59 项：已归档会话仍算占用模型（它们保留了模型选择，移除后恢复会出错）；报错里会标出"已归档"。
- 第 67 项：默认模型下拉里保留演示模型（它是初始默认值）。
- 第 72 项（C7）：进化历史没有改成存代码再翻译；改为宿主写入时按语言表翻译，并加了一致性测试。
- 第 73 项（F86）：记忆同步面板没有加"知道了 / 重新提炼"（重新提炼是付费调用，确认需要记忆同步模块的持久写入）；改为说明性提示。
