## 1. 推理档位：按供应商/模型自动适配 + 自动路由（P0 + P2）

### 1.1 能力模型（参考 Harness `llm/llm/src/types.ts` 的 `reasoning.efforts/defaultEffort`）

每个模型的推理能力由宿主适配器给出，而不是全局固定词表：

```ts
type ReasoningCapability = {
  control: 'effort' | 'toggle' | 'budget' | 'adaptive' | 'none'; // 供应商实际控制方式
  efforts: { id: string; label: string }[];   // 该模型当前实际支持的档位（顺序即强弱）
  providerDefault?: string;                    // 已知的供应商默认档位；未知则不填
  visibility: 'full' | 'summary' | 'hidden';   // 是否返回思考原文
};
```

来源优先级：供应商发现接口返回的 `supported_reasoning_levels/default_reasoning_level` > 预设目录（带官方来源与核对时间）> 协议推断（Anthropic adaptive、DeepSeek/GLM/Qwen 开关）> 无推理。发现结果变化时自动刷新，不需要用户重新配置。

### 1.2 选择值

| 值 | 含义 | 请求行为 |
|---|---|---|
| `auto`（新默认） | 每轮由 JEV 在该模型 `efforts` 中选择 | JEV 不可用、弃权或超时 → 等同 `default` |
| `default` | 供应商默认 | 省略档位参数，只按需打开思考开关（Harness 的 provider default） |
| 具体档位 | 用户手动固定 | 映射到供应商字段；不支持时拒绝而非静默降级 |

- 轮次记录 `modelConfig.reasoning = { requested, effective, source: 'jev' | 'provider-default' | 'user' | 'rule', rationale? }`，界面显示「自动 · 本轮 medium」。
- 迁移：`defaultModel` 及未显式选择过档位的会话迁移为 `auto`；用户显式选择的保留。
- 规则快速通道（零延迟）：计划模式、明确要求「仔细想」、上一轮失败重试等直接给出档位，不调用 JEV。

### 1.3 思考可见（P0 后端 + P1 界面）

- 宿主不再丢弃 thinking：增量事件 `block.delta{kind:'thinking'}` 推送到界面，块结束时持久化。
- `visibility: 'hidden'` 的模型显示「思考中 · 计时 · 已用 token」。
- 首 token 前显示「正在连接模型」，记录 TTFT；工具参数流式到达时显示「准备读取 …」。

## 2. 数据通路（P0）

参考 Harness：会话以追加日志为事实来源，投影缓存供冷读；非会话数据用有 schema、可发变更事件的 KV 域（JSON / SQLite 后端）。Pi 的会话同样是每会话 JSONL。

### 2.1 分片持久化（内存模型不变）

- 内存中的 `state` 形状保持不变，现有逻辑与测试无需改动。
- `persist()` 把状态拆成分片：`core.json`（索引、配置、事件等）、`sessions/<id>.json`、`projects/<id>/{versions,jobs,decisions,learning,initiative}.json`；只重写内容哈希变化的分片，并原子写入。
- 启动时从分片组装；兼容读取旧的单文件 `state.json` 并自动迁移（迁移前保留一份旧文件，迁移成功后删除）。
- 流式展示增量只存在内存（已有 `projectRuntimeDisplay` 语义），块/轮结束才持久化。
- OpenViking 仍是唯一记忆后端，存储重构不触碰记忆服务与其回执。

### 2.2 增量事件协议 v2（详见 `docs/specs/stream-protocol-v2.md`）

- `GET /api/v2/stream?session=<id>`：有类型事件 + 单调序号 `seq`，支持 `Last-Event-ID` 续传；背压时发送 `resync`。
- 轻量读取：`GET /api/v2/bootstrap`（项目/会话索引、配置摘要，不含条目）、`GET /api/v2/sessions/:id`（条目与轮次）、项目重数据按视图分别读取。
- 旧 `/api/state`、`/api/stream` 保留给 CLI 与旧界面，直到新界面完成替换。

### 2.3 清理与保留

- 已清除 45 个 `state.json.before-*`。检查点（5.3GB）与旧发布包（6 个）在部署新版本、重启服务时一并清理并重写维护登记表。
- 新增保留策略：检查点最多 3 个、发布包只保留当前与上一个；快照写入 `.state/snapshots/` 并设总量上限。
- `desktop/dist` 16GB 为历史 DMG 构建产物，待用户确认后清理。

## 3. 工具分层（P2，参考 Pi 与 Harness）

| 层 | 内容 | 声明方式 |
|---|---|---|
| 通用核心工具 | 读、列目录、查找、搜索、编辑、写入、执行命令、网页搜索/抓取、`skill` 加载、向用户提问 | 所有用途（前台、后台、学习、评测）声明同一套、同一顺序；权限在执行时拦截，并在尾部上下文说明本次授权 |
| 技能 | 项目已分配技能 | system 之后的稳定目录只含摘要；由 `skill` 工具按需注入全文（Harness `tool-skill`） |
| MCP | 项目或聊天专用 | 项目固定常用服务器以原生工具声明（随项目低频变化）；其余通过 `mcp` 加载器按需读取 schema 并调用，保持工具数组稳定 |

执行时拦截返回明确回执（「当前为只读授权，写入被拒绝」），不静默失败。

## 4. 缓存覆盖率（P2，参考 Pi）

1. **分层前缀**：`[Rna 基础规范 + 核心工具] → [项目快照（按版本低频更新）] → [用途说明] → [动态尾部]`。授权级别、时间、版本 ID、节奏状态等变化值全部移到尾部上下文消息。
2. **跨用途共享**：前台、后台判断、后台执行、学习共用前两层，后台请求命中前台已写入的缓存。
3. **按用途计量**：每次请求带 `purpose`（foreground / initiative / background-work / jev-llm / learning / evaluation / compaction / summary / initialization），`GET /api/v2/usage/cache` 按用途与时间窗给出命中率、加权覆盖率和冷启动次数；界面上下文面板展示。
4. **后台唤醒对齐 TTL**：非紧急后台判断优先安排在最近一次同前缀请求的 TTL 窗口内。
5. **保温**（后续）：Pi 式按成本判断，需要先补模型价格表；缺价格或 TTL 时不启用。

## 5. JEV：更多决策交给快速判断（P2）

原则：JEV 负责「在已知选项中快速打分/选择」；选项由宿主模板或主模型给出；权限、采纳版本、执行副作用仍不由 JEV 决定。

1. **宿主模板问题**：新增 `host-template` 计划来源。模板由宿主版本化并计算哈希，可审计；与现有「主模型编写计划」并存。
2. **决策点扩展**：
   - `chat.route`：一次请求同时给出推理档位（choice，选项 = 当前模型的 `efforts`）、是否需要记忆（boolean）、候选技能预加载（最多若干个 boolean）。与记忆召回并行执行，隐藏召回延迟。
   - `initiative.review`、`evolution.review`：保持现有逻辑。
   - `skill.screen`、`candidate.prescore`：为 P4 预留（见第 7 节）。
3. **两种后端**：TypeSafe System One（`jev-latest`）；未配置时可选「判断模型」后端，即用已配置的快速模型（关闭思考、JSON schema、小输出上限）实现同一 `decide` 接口。两者都没有时按规则与供应商默认处理。
4. **校准**：真实结果（采纳或回复主动消息、忽略、失败、用户纠正）写入 ledger，作为阈值调整的标签。先 shadow 再 active，并按用途统计延迟与 token。
5. **性能目标**：`chat.route` 预算 ≤ 900ms，超时即回退，不阻塞主请求。

## 6. 主动沟通（P3，参考 Headlong）

1. 前台回复与后台工作分开取消：普通追问不中止后台只读任务，只有明确停止才取消；后台产出使用最新上下文重新判断是否投递。
2. 消息写作规范写入主动消息提示词：先说结论；不出现内部 ID、路径、哈希；不发状态汇报式消息；附「过去 24 小时已发送」清单用于去重。
3. 每次后台运行结束写一句交接（Headlong `FINAL`）：做了什么、剩什么、下一步。作为下次唤醒上下文，便宜且有利于缓存。
4. 分级触达：对话内插入、收件箱、桌面通知、每日摘要。紧急度由主模型给出，是否打扰由用户设置和 JEV 共同决定。
5. 卡住时主动提问，使用带选项的交互卡片。
6. 指标：有用主动消息率、回复/采纳率、忽略率、误静默，同时作为 JEV 校准与进化信号。

## 7. 自进化：每个项目是一个独立 Agent（P4，遵循 RRSI）

### 7.1 定位

- 每个项目 = 一个独立 Agent（类似 Claude Code / Harness 的 agent preset）：系统提示词、技能、工具与 MCP 分配、节奏与沟通策略、评测标准共同构成它的「基因组」。
- 进化以该项目定义的**任务类型**为单位，例如调研、编码、创作、周期任务。
- 整个 Rna 系统是更大范围的自进化系统：汇总各项目的真实信号，进化通用组件（核心提示词、工具描述、JEV 模板、沟通规范）。

### 7.2 初始化：先装基础技能，缩短进化迭代

1. 根据项目标题、介绍与任务类型生成检索词（不含私有内容与密钥）。
2. 在技能市场**先检索出候选列表**，由宿主读取元数据（名称、描述、来源、维护情况、兼容性）。
3. **JEV 快速筛选**：每个候选一个 boolean「是否适合该项目任务类型」，加上一个整体 score；高置信的直接入选，模糊的交给主模型复核。
4. 安装入选的完整技能包（沿用现有固定包、校验与权限不自动扩大的规则），作为基线基因组 H₀。
5. 替代当前「模型主导最多 5 次调研请求」的做法，降低 `partial/failed` 比例。

### 7.3 迭代（RRSI 方法论）

| RRSI 机制 | Rna 实现 |
|---|---|
| 可编辑组件与标签 | 组件注册表：system 段落、技能、工具描述、MCP 分配、节奏、沟通风格、评测标准。每次编辑标注组件、假设、diff |
| 退火编辑预算 | 前几轮允许捆绑多个编辑，逐轮收紧到 1–2 个 |
| 完整编辑历史 | 记录假设、得分变化、成本变化与裁决；已证伪的假设不重复提出 |
| 停滞探索 | 连续无进展时引导去改从未尝试过的组件 |
| 评测前审查 | 便宜的审查器挡掉针对用例的投机与无效机制，最多修复一次 |
| 噪声带与成本规则 | 重复运行基线估计噪声；新增 token 必须由可测收益覆盖 |
| 裁剪 | 长期未起作用的组件进入删除候选 |
| 候选即提交 | 基因组用 git 管理；候选在独立 worktree，采纳为快进合并，回滚为 revert |

### 7.4 信号与权重

- 主信号来自真实交互：用户纠正、重试、中止、工具失败、过长轮次、主动消息被采纳或忽略、交付物被保留或回滚。这些会转成可回放用例（工作区快照 + 输入 + 检查项），并留出一部分用于泛化检验。
- JEV 对比打分作为先验：候选得分 = `w_real · 真实交互/回放得分 + w_jev · JEV 对比分`，默认 `w_real = 0.8`、`w_jev = 0.2`。真实信号不足时，JEV 只能决定「是否进入评测」，不能单独让候选被采纳。
- 分层评测：审查 → 3 个用例冒烟 → 完整评测，只有通过前一层的才进入下一层。

## 8. 前端重构（P1）

### 8.1 技术栈

- Vite + React 19 + TypeScript + Tailwind v4（设计 token 用 CSS 变量）+ Radix 基础组件 + Zustand + TanStack Virtual + Shiki。
- 动画：**Motion**（布局、进出场、手势、共享元素）+ **GSAP**（高性能时间线、文字拆分、滚动与复杂编排）+ **ReactBits**（通过 shadcn 注册表按需复制 TS-TW 组件源码，再按设计系统改写）。
- 性能约束：动画只用 transform 和 opacity；长列表虚拟化；WebGL 背景只用于空状态和引导页，工作区不常驻；遵守系统「减少动态效果」设置；主线程任务单次不超过 50ms。
- 构建产物为静态文件，由 daemon 提供，daemon 仍然零第三方运行依赖；未构建时显示构建说明页（旧界面已移除）。

### 8.2 视觉

保留现有浅色蓝灰中性色、R 标识和 PingFang。完整设计 token：8pt 网格、4 级文字层级、1 个强调色、同时支持深色模式。正文 15px、行高 1.7，并针对中文排版单独调整。界面不出现内部 ID 与实现术语。

### 8.3 对话时间线（参考 Harness `ui-chat`）

- **过程头**：「正在深入 · 38s」/「已处理 1m12s」，可折叠，显示实时计时。
- **思考**：单行预览（最近一段已写完的首行 + 扫光），展开为完整 Markdown，结束后显示「已思考 14s」。
- **工具行**：单行，图标 + 动词 + 对象 + 附加信息；同类连续调用合并（「读取了 6 个文件」）；点击后在右侧查看详情。
- **命令**：终端块，支持 ANSI 颜色、实时输出、头尾截断、退出码与耗时。
- **文件编辑**：行内 diff 卡片（+12 −3），右侧审阅面板显示完整 diff。
- **交付物**：轮次末尾「本轮交付」区，包括改动文件汇总与产出文件卡片（文档、预览、链接）。
- **沟通记录**：主动消息带来源与时间，提问卡片，投递状态；收件箱视图。
- **最终回答**：干净的 Markdown，不重复身份抬头。
- **输入框**：模型与推理合并为一个胶囊（「GLM-5.3 · 自动」）；权限胶囊；排队区；停止按钮；修复「回到最新」遮挡。

### 8.4 页面

对话、轨迹（参考 Harness 轨迹视图）、任务、版本（进化更新日志）、观察、文件、设置（模型、记忆、自主、维护）。右侧为可停靠面板：文件、预览、审阅、工具详情、终端。

- 子代理：`agent_claude_consult` 默认后台（同 `agent_consult` 的句柄、通知、`agent_status/wait/cancel`、重启中断语义，答案不入记录）；`agent_status`/`agent_wait` 读到结果时撤回仍排队的完成通知，修复重复读取。
- 维护接续：停机后接续（如人工越过锁定）在启动目标前运行原生读取预检（新阶段 `native_preflight_start`），失败则不启动、保持暂停并说明权限原因，不再静默挂起。
