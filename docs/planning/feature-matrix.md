# 功能清单与验收矩阵

下表为完整目标产品需求；“实现来源”记录原设计参考，不代表全部完成，也不代表依赖 Pi SDK。当前实际实现以 Rna SDK 0.4 / 控制平面0.10的[接入矩阵](../rna-sdk.md)和验证记录为准。已落地动态能力安装、技能按需加载、前台读写执行、无 Goal 持续主动循环和渐进项目记忆；已接入可执行项目能力包、冻结标准的基线/候选评测及真实版本切换；外部保留集质量验证、发行与生产隔离仍待完成。阶段：S=技术验证，M=MVP，V=v1，R=后续研究。优先级：P0必需，P1重要，P2可延期。

本轮保留原有 75 个功能 ID，并新增 8 项项目主动协作需求。交互层级为 `Project → Session → Turn/Step`；自主控制为 `Project → Observation/OpenLoop → Decision → Run/Message/Silence`，Goal 为可选关联。主动发现、注意力调节和项目自主候选评测进入 MVP 主线，范围与估算同步调整；原型仍须单独说明模拟边界，不把目标需求视作已交付。

## 2026-09-25 核心能力改造

本轮已落地稳定执行方法、真实目录导读、四项按需方法技能、可恢复的交付检查、隔离产物对照评估、零工具初始化、进化修复无变化早停，以及主动行动交接/历史读取。新增能力的实际质量证据见专业能力重构；网页功能通过、研究纠正和候选预检失败分别记录，不能合并成专业质量已经通过。

后台结果核对现支持“已完成”“确认未执行”“已检查并终止、结果未验证”，UI/CLI 共用实际状态校验；晚到的未决命令结果不会在取消竞态中丢失隔离。图像内容链路与模型输入能力声明也已接入，视觉能力必须与实际支持的模型匹配。所有实现/测试与真实模型的覆盖边界以最新验证记录为准。

继续对齐参考项目的改动包括：官方浏览器 MCP 预设与会话生命周期、Agent 可调用的静态预览及聊天分屏入口、私有命令日志分页、未决事项的新证据唤醒、失败工具回执交接、候选脚本夹具及冻结评估集继承。参考机制和实际质量门槛见对齐验收矩阵。新增独立进化任务已真实执行两组，双方产物均正确，尚未测出提升；不能把“能够评估”写成“已经持续变强”。

持续学习另接入独立持久生命周期：工作路由不再占用学习机会，普通聊天不取消已冻结实验；原始证据、候选生成、失败恢复、共享预算与实际通过后的通知均有独立身份。真实复盘已自然触发实验，作者失败也保留原始记录；最新模型结果见验收记录。这补齐了调度与来源缺口，任务级浏览器/服务评估、专业质量及长期稳定性仍按实际证据验收。

## 跨模块验收场景

1. CLI在项目Session中发起一轮工作，桌面实时attach并steer；该轮结束后同会话继续下一轮，daemon重启后会话、执行与输入只出现一次。
2. LLM发出外部写工具，工具执行成功但返回断线；恢复显示待核对，不能重发。
3. MCP服务更新schema；当前run不随机漂移，新run采用新manifest并解释cache序列变化。
4. OpenViking不可用；任务仍可使用已有会话上下文，记忆不可用清楚可见，不切换本地记忆库。
5. 候选skill在开发集提高但保留集退化；系统拒绝晋级并记录费用。
6. 用户缩小目录授权；旧run的缓存与记忆不能继续泄露被撤销内容，broker立即拒绝动作。
7. 窗口关闭后台继续；急停后所有worker无法取得新预算或工具租约。
8. 项目没有Goal，观察到依赖变化后自行检查并在当前项目对话解释发现；用户未发新消息也能收到一次主动沟通。
9. 用户正在输入时，后台评测完成；候选邀请延迟且草稿/焦点不变，用户插话后先结合新事实重评邀请。
10. 项目A生成并评测更优候选，主动邀请试用；项目B保持旧版本、没有A的消息/记忆/指标。试用A后新run固定候选版本，回滚不改变在途run。

## 会话交互专项验收

这些场景是既有 ID 的具体通过条件，随对应 MVP/v1 功能交付；尚未接真实执行器的交互原型只能验证模拟路径。

| 关联ID | 场景 | 可观察结果 |
|---|---|---|
| RUN-01、UI-03 | 起步与继续 | 选择工作区后直接输入，不先填写任务表单；第二条需求进入同一Session的新Turn |
| RUN-01、RUN-02 | 会话与目标分离 | 普通请求不创建长期Goal；设定Goal后可跨Turn/Run推进，会话始终可继续 |
| RUN-05、UI-03 | 执行中follow-up | 当前轮继续，补充内容进入待处理dock；可文本编辑或移除，尚未执行不伪装为已接收回答 |
| RUN-05、UI-03 | 执行中steer | 当前执行在下一可接收边界处理纠正，明确区分待接收/已接收；不悄悄替换成下轮请求 |
| RUN-03、UI-03、UI-10 | 停止与输入共存 | 运行中仍可编辑；空草稿可停止本轮，有草稿可发送/排队；暂停目标与全局急停不混同 |
| `UI-03` | 过程与结果层次 | 活跃工具保留状态；成功完成过程可收起、最终回答仍可见；停止/失败原因和已执行活动不隐藏 |
| UI-03、UI-10 | composer生命周期 | 权限/模型/附件与共用指令菜单在输入区，计划模式明确可见；未配置模型时仍可选择模型，附件未就绪禁止漏传，审批后恢复草稿 |
| UI-04、UI-07 | 渐进披露 | 初始资源栏关闭、空目标/队列不占位；点击文件/工具/计划才打开相关内容；管理入口不抢占默认对话 |
| `UI-11` | 切换与恢复 | Session A草稿和资源不进入B；刷新后输入不重复，阅读旧消息不被流式更新拉回底部 |
| RUN-14、UI-04 | 子代理查看（v1） | 主会话能打开关联子会话，正文不被代理列表淹没；one-shot只读、continuable按能力接受输入 |
| CAC-02、UI-03、UI-09 | 呈现与缓存隔离 | 折叠过程、开关资源栏、切换检查视图不改变Rna模型请求内容；缓存数据缺失显示未知或未连接 |

上述新增验收至少包含无 Goal、无需用户继续发命令、主动消息延迟、坏候选拒绝、好候选通知、试用/回滚及跨项目隔离。固定七步 Goal 演示不能替代这些通过条件。
